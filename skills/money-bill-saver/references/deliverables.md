# Deliverables and optional verification

Default language is English unless the user asks otherwise. Keep source quotations and identifiers in their original language. Store real mail, attachments and pages in a private task directory.

## Default focused report

- `quick.json`: compact decisions and source references under [quick-model.md](quick-model.md).
- `dashboard.json` and `dashboard.html`: generated by `scripts/build_quick_report.py`. The self-contained webpage is the primary deliverable.
- Optional `source_index`: saved candidate/message/attachment locators. Keep selected originals available for follow-up; do not copy every irrelevant message into the report.

The page shows Current services, Refund questions and Other issues, plus a monthly cost sheet sharing the service inventory. Include named services without receipts as unknown. Show observed last invoice, successful charge and next renewal separately, with unknowns where needed. The monthly subtotal states which current costs it includes and which are missing. Routine one-time purchases with no issue belong in a compact appendix.

Draft text belongs inside the relevant case. Separate CSV, Markdown narrative, spreadsheet, per-draft files and full source timelines are optional exports on request. A private page does not authorize hosting its financial or mailbox data.

Use the fixed renderer and the short [webpage preflight](web-design.md). Check the three sections, cost sheet and visible scope once. Open the full design guide only for template changes.

## Optional independent verification

The default focused page is labeled as such and has **no second-agent review**. Invoke the separate `$money-bill-saver-review` skill only when the user requests an independent check. Give that agent the saved report and originals; it checks consequential costs, dates, refund/payment drafts and later outcomes. Record its actual findings and limitations.

For an explicitly requested exhaustive `audit-1` audit, create the complete evidence bundle, then read [the evidence contract](audit-evidence-contract.md). `prepare_review.py` prepares bounded packets; it does not itself verify facts. A reviewer reads the material originals and checks discovery, exclusions, costs and all entities. `check_audit.py` and `render_dashboard.py --require-checked` apply only after that bound review. A source-scope pass cannot prove that an unsearched mailbox message does not exist.

Benchmark first-output traces, frozen proposals, screenshot sets and timing tables are produced only for a requested performance evaluation. Compare live runs with the same account, window and model settings; record both the first page and any later optional review separately. Stop at an exceeded phase budget and keep the handoff artifacts for diagnosis.

## Drafts and outcomes

For a supported merchant request, include the observed invoice or account reference, timeline, amount, question or requested remedy, and the material evidence. Attribute user-reported non-use. Keep refund requests separate from cancelling future renewal. When the seller requires an account session, give ready-to-paste text and the official entry point; do not invent a submission receipt.

Only a matched transaction verifies a cash refund. A merchant promise is pending, a waived unpaid bill is not cash returned, and a spending cap is future protection. When the user authorizes an external action, retain its confirmation and update the outcome from actual evidence.
